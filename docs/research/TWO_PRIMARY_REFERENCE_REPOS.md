## Cadence — learning architecture

- [README](https://github.com/pstepanovum/Cadence/blob/e97a87584716868925ea94fc0e540f3cf309a2f8/README.md): Next.js 16, React 19, Firebase, Python speech and coach engines, guided Learn/Conversation/AI Coach experiences, Electron and mobile. These are separate infrastructure choices, not requirements for Eng Teacher.
- [src/lib/conversation.ts](https://github.com/pstepanovum/Cadence/blob/e97a87584716868925ea94fc0e540f3cf309a2f8/src/lib/conversation.ts) defines learning scenarios with level, focus, ordered turns, expected response and coaching cue; [ConversationSession.tsx](https://github.com/pstepanovum/Cadence/blob/e97a87584716868925ea94fc0e540f3cf309a2f8/src/components/conversation/ConversationSession.tsx) uses explicit phases (intro, coach, recording, assessing, result, done). We should create our own small typed exercise definition, not copy its curriculum.
- [PracticeLesson.tsx](https://github.com/pstepanovum/Cadence/blob/e97a87584716868925ea94fc0e540f3cf309a2f8/src/components/learn/PracticeLesson.tsx) organizes targeted retries and feedback. [src/lib/pronunciation.ts](https://github.com/pstepanovum/Cadence/blob/e97a87584716868925ea94fc0e540f3cf309a2f8/src/lib/pronunciation.ts) separates target, transcript, phoneme results and timing instead of pretending ASR text grades pronunciation.
- [phoneme_scorer.py](https://github.com/pstepanovum/Cadence/blob/e97a87584716868925ea94fc0e540f3cf309a2f8/src/backend/ai-engine/phoneme_scorer.py) decodes speech audio and uses Wav2Vec2 phoneme inference (pinned model revision in source). [speech_transcriber.py](https://github.com/pstepanovum/Cadence/blob/e97a87584716868925ea94fc0e540f3cf309a2f8/src/backend/ai-engine/speech_transcriber.py) defaults to English-only openai/whisper-base.en, NOT a replacement for our Hindi-English STT. FastAPI endpoints in [main.py](https://github.com/pstepanovum/Cadence/blob/e97a87584716868925ea94fc0e540f3cf309a2f8/src/backend/ai-engine/main.py) use model warmup. [Stubbed endpoint tests](https://github.com/pstepanovum/Cadence/blob/e97a87584716868925ea94fc0e540f3cf309a2f8/src/backend/ai-engine/tests/test_endpoints.py) verify input limits, not actual pronunciation quality.
- [Engine requirements](https://github.com/pstepanovum/Cadence/blob/e97a87584716868925ea94fc0e540f3cf309a2f8/src/backend/ai-engine/requirements.txt) include Torch, Transformers, Omnivoice and audio utilities. [Coach requirements](https://github.com/pstepanovum/Cadence/blob/e97a87584716868925ea94fc0e540f3cf309a2f8/src/backend/coach-engine/requirements.txt) include an unpinned Git checkout of Transformers, increasing reproducibility risk. Root MIT does not settle model-weight, voices, training data or all third-party asset terms. No such models have been downloaded.
- Recent source activity (8 Nov 2026), [multi-target CI](https://github.com/pstepanovum/Cadence/blob/e97a87584716868925ea94fc0e540f3cf309a2f8/.github/workflows/ci.yml) and a substantial test tree are promising maintenance signals, not a product-quality guarantee. We did not run its model suite.

**Integration boundary:** adopt the *design* of structured exercises into our existing InterviewTutor. No Firebase, Stripe, Electron, parallel tutor services or borrowed lesson assets. Learning design value is high, small lesson schema effort low/medium; full self-hosted pronunciation scoring compute, integration and licensing cost high/unknown.

## Talking Avatar — browser visual teacher

- [README](https://github.com/InterviewFlowAI/talking-avatar/blob/d3e4dcf6609d733097466eb17b3fa63fc720140a/README.md) and [package.json](https://github.com/InterviewFlowAI/talking-avatar/blob/d3e4dcf6609d733097466eb17b3fa63fc720140a/package.json): version 0.3.0, ESM, React >=18 and Three >=0.160 peer support; no dedicated ML inference server. [React wrapper](https://github.com/InterviewFlowAI/talking-avatar/blob/d3e4dcf6609d733097466eb17b3fa63fc720140a/src/react.tsx) accepts stream and status.
- [src/TalkingAvatar.ts](https://github.com/InterviewFlowAI/talking-avatar/blob/d3e4dcf6609d733097466eb17b3fa63fc720140a/src/TalkingAvatar.ts) uses AudioWorklet to inspect incoming audio, and a browser AudioContext delay (default 150 ms) **plays the audio itself** via destination. [VisemeDetector](https://github.com/InterviewFlowAI/talking-avatar/blob/d3e4dcf6609d733097466eb17b3fa63fc720140a/src/visemeDetector.ts), [VisemeModel](https://github.com/InterviewFlowAI/talking-avatar/blob/d3e4dcf6609d733097466eb17b3fa63fc720140a/src/visemeModel.ts) and [renderer](https://github.com/InterviewFlowAI/talking-avatar/blob/d3e4dcf6609d733097466eb17b3fa63fc720140a/src/renderer.ts) derive mouth shapes from real audio and animate eyelids/brows. [Model parity test](https://github.com/InterviewFlowAI/talking-avatar/blob/d3e4dcf6609d733097466eb17b3fa63fc720140a/test/visemeModel.test.ts) compares outputs to a PyTorch fixture; does not verify our LiveKit barge-in or low-cost Android performance.
- The upstream README describes MIT-licensed binary viseme model and Microsoft Rocketbox-derived GLB characters, with a separate avatar MIT notice. Model training uses LibriTTS-R per README: independently verify training provenance and downstream terms before commercial redistribution. CDN default should become self-hosted files in a production trial. [CI](https://github.com/InterviewFlowAI/talking-avatar/blob/d3e4dcf6609d733097466eb17b3fa63fc720140a/.github/workflows/ci.yml) checks Node 20/22/24, types, tests, build and package. Last inspected commit: 2 Nov 2026.
- **Audio ownership blocker:** Eng Teacher already uses LiveKit RoomAudioRenderer. Calling attachStream on the same remote teacher track **and leaving RoomAudioRenderer playing it** would double-play sound and complicate interruptions. Never attach the learner's mic. In a future experiment choose exactly one audio owner, isolate only the agent's audio track, test autoplay, mute, unplug, reconnect and interruption cleanup, and fall back to LiveKit audio if avatar fails. Do not add this package to the current production lockfile until that experiment is tested.
- Upstream claims small model and low CPU cost; those are not measurements for our mobile hardware. Expect extra browser GPU use, download and support costs; no proven extra server lip-sync inference cost. Integration medium effort, high audio-regression risk, educational value still to validate.

## Selection over the other 19 references

The [21-repo inventory](OPEN_SOURCE_REPOSITORIES.txt) includes two official LiveKit starters (already integrated), and 17 other candidates for narrower or later needs: parallel voice transports, TTS/STT alternatives, standalone tutor apps, scoring alternatives, FSRS, QA, authentication, fine-tuning, inference and native mobile. Of the additional candidates, Cadence gives the clearest structured-teaching reference, while Talking Avatar addresses the missing visual tutor. Neither requires replacing the voice transport. License restrictions of other references (e.g. ThirtyTutors noncommercial, FreeSurf GPL with extra terms) reinforce studying concepts instead of bulk code imports.

## Adoption decisions

Use the [core Cadence audit](../../AnalyseFuture/recovery/features/CADENCE_WEB_SEMANTIC_AUDIT.json)
and [client and avatar audit](../../AnalyseFuture/recovery/features/CLIENTS_AND_AVATAR_SEMANTIC_AUDIT.json)
for component locations, responsibilities, dependencies, test scope and risks.
The [recorded reference checks](../development/MODULE_VALIDATION.md#isolated-reference-validation)
covered 470 isolated Cadence pure-module tests and 16 isolated Talking Avatar
DSP/model tests. Those results describe the preserved revisions.

| Reference capability | Decision and Eng Teacher destination |
| --- | --- |
| Cadence scenario focus, ordered turns and short feedback loops | **ADAPT.** Original work-update and train exercises live in [web practice](../../apps/web/features/practice/). Café order uses the existing [signed lesson catalog](../../services/voice-agent/src/eng_teacher/teaching/lessons.py) and its worker-owned prompts. No Cadence curriculum or code is imported. |
| Cadence guided retries, captions and summaries | **MERGE.** The active [teaching policy](../../services/voice-agent/src/eng_teacher/teaching/) and [lesson UI](../../apps/web/features/lesson/) already own these behaviors. Keep one event contract and tutor state machine. |
| Cadence progress model, native lesson packs, placement and spaced review | **RESEARCH.** Revisit pure scheduling and progress logic after educator review and consent design. Local and cloud clients remain recovery references. |
| Cadence phoneme scoring, local transcription and speech synthesis | **DEFER.** Evaluate scoring on consented recordings with alignment and human judgments. The archived English-only ASR, Torch/model dependencies and separate model/content rights require review. |
| Cadence desktop downloader, Firebase/Electron/native stacks and shared assets | **DEFER** the downloader pending independent integrity verification. Keep the standalone stacks and content in provenance archives. The documented asset and data terms apply independently of MIT. |
| Avatar stream isolation, mouth motion and cleanup | **ADAPT.** The [Eng Teacher avatar feature](../../apps/web/features/avatar/) analyzes remote teacher audio while LiveKit owns playback. It uses original visuals and imports no upstream SDK, weights or characters. |
| Avatar WebGL renderer, visual-speech inference and GLB characters | **DEFER.** Review model and training provenance, attribution and low-end device performance before integrating these bundled components. |
| Expanded reference projects | **REMOVE** the duplicate working-tree expansions. Both original ZIPs, license notices and the exact [Git recovery revision](../../AnalyseFuture/original-projects/reference-sources/README.md) preserve every source payload. |
