ENG TEACHER — OPEN-SOURCE REPOSITORIES WE DISCUSSED
======================================================
Updated: 2026-11-15
Project: https://github.com/Planeshiffhter/eng-teacher
Purpose: One reference inventory so Codex and other developers can find,
evaluate, and selectively reuse existing public projects instead of
rebuilding everything.

VERIFICATION
------------
All 21 GitHub URLs below were checked against the GitHub API on
2026-11-15 and existed as public repositories at that time. The license
labels below summarize the visible repository metadata or LICENSE file.
This is NOT a legal audit of dependencies, bundled assets, weights,
characters, audio voices, or proprietary content. Read current LICENSE
and third-party notices at the actual revision before commercial use.

DECISION RULES
--------------
* Keep ONE main product repository: Planeshiffhter/eng-teacher.
* Reuse official packages and minimal compatible modules, not complete
  competing applications with overlapping frontends/backends.
* "Study" means examine architecture and learn patterns. Do not copy
  proprietary branding, premium content, character designs, or code
  from noncommercial repositories into a commercial product.
* If a component already works in the main repo, DO NOT rebuild it.
* Integrate only after checking license, tests, latency, and maintainability.
* An open-source library is not necessarily a free hosting service.

RECOMMENDED ORDER FOR CODEX
---------------------------
1. READ current eng-teacher code and reuse working LiveKit integrations.
2. Stabilize correction/retry/explanation state and regression tests.
3. Test a real English/Hindi microphone-to-speaker lesson with
   credentials configured securely outside Git.
4. Add consent-safe usage/latency/cost monitoring.
5. Integrate ONE avatar solution, keeping audio-only fallback.
6. Add educator-reviewed exercises and audio pronunciation testing.
7. Add learning accounts/history, then FSRS and personalized lessons.
8. Add additional native languages after speaker testing.
9. Fine-tune a Qwen adapter only after consented reviewed examples,
   held-out evaluations and a proven baseline.
10. Implement self-hosted inference/mobile/billing only when justified.
